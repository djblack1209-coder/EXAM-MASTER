# 移动端设计方向与解耦准则

> 状态：设计基线
> 更新日期：2026-04-30
> 适用范围：iOS / Android App、H5 移动端壳、后续可复用到微信小程序的共享组件与业务模块
> 目标：在开始页面重构前，先锁定移动端的商业化现代审美、模块边界、资产策略和验收口径

## 一、定位判断

移动端是 `EXAM-MASTER` 的主力产品，不是小程序的放大版。小程序承担轻量入口和提审发布，小包体、低页面数、极简链路优先；移动端承担全功能、完整刷题闭环、资料导入清洗、知识图谱、FSRS 复习、错题资产和长期留存。

目标用户集中在 23-35 岁。设计要让用户觉得这是一个成熟、可信、效率高的备考产品，而不是机构题库后台、儿童刷题游戏或泛 AI SaaS 模板。最终气质应接近现代商业 App：有 Wise 的清晰可信、有 Bitget 的信息密度和操作效率、有 Duolingo 的节奏反馈，但去掉低幼吉祥物和夸张游戏包装。

## 三、硬性设计原则

### 3.1 必须做到

- **商业化但不冷冰冰**：界面第一眼要有品牌质感，核心任务要像金融/效率工具一样清楚。
- **精致但不炫技**：玻璃态、拟物态、动效只为表达层级、按压、状态和进度服务。
- **数据可信优先**：题库覆盖、答案证据、掌握率、剩余复习量、清洗状态要比装饰插画更优先。
- **模块像积木**：每个业务能力先有独立边界、输入输出、状态和测试口径，再装进移动端壳。
- **重复流程归一**：移动端原有上传资料解析入口保留，小程序端入口也保留，但背后只能共用一套资料导入/清洗/题库发布能力。

### 3.2 明确禁止

- 禁止用 emoji 当功能图标、导航图标、成就图标或空状态主视觉。
- 禁止猫头鹰、博士帽、火焰、金币、奖杯、火箭、儿童卡通人物等低幼游戏化素材。
- 禁止泛 AI 感：紫蓝渐变大背景、发光圆球、抽象 bokeh、无意义光带、机器人助手脸。
- 禁止考试机构后台感：灰白表格、硬边列表、堆字段、行政系统式按钮。
- 禁止卡片套卡片和满屏卡片汤。一级页面可以有材料面板，重复列表项必须克制。
- 禁止营销站首页替代 App 首页。首屏必须能开始学习、继续刷题或查看下一步任务。
- 禁止为视觉统一牺牲可读性。玻璃层上文字必须有足够对比，不能靠背景模糊碰运气。

## 四、视觉语言

### 4.1 色彩

主色继续使用 Wise 绿方向，但移动端不能被单一绿色吞没。移动端的长期使用场景需要避免纯白背景带来的审美疲劳，建议改为“绿白蓝清醒系统”：绿色负责品牌和行动，白色负责阅读与留白，蓝色负责信息、同步、清洗进度和冷静感。推荐比例：

- 45% 浅薄荷、绿白渐变和低噪声冷雾底，用作页面背景和大面积环境色。
- 20% 深绿、墨绿、近黑，用作品牌面、关键标题、沉浸式训练舱。
- 20% 玻璃白、雾白、半透明浅绿，用作内容阅读区、一级材料面板和浮层。
- 10% 冷蓝、浅天蓝、蓝青，用于同步、AI 分析、清洗队列、信息状态和轻盈感。
- 5% 琥珀/红色等强语义色，用于风险、倒计时、错误和阻断状态。

辅助色建议只保留明确语义：琥珀表示待处理/倒计时，红色表示错误/风险，蓝青表示同步/信息/清洗完成，紫色只能少量用于 AI 分析标签，不能成为主视觉。蓝色必须偏清澈、克制、低饱和，不能变成金融交易盘或医疗后台的冷蓝。

### 4.2 材质

移动端可以使用玻璃态和轻拟物态，但要分层：

- **导航与浮动操作层**：可用高质量玻璃，表达悬浮和可触达。
- **训练/复盘主面板**：可用轻拟物态，强调可按压、可翻转、可拖拽。
- **内容阅读区**：优先实色和低噪声 surface，保证长题干和解析可读。
- **重复数据项**：用紧凑浅面、细边线和小阴影，不做大圆角玻璃卡片。

圆角规则：

- 页面级材料面板：`24rpx-40rpx`，用于首屏主面板、底部操作条、沉浸训练舱。
- 重复列表项/数据卡：`12rpx-16rpx`，优先可扫描和稳定布局。
- 小按钮、筛选 chip、图标按钮：按控件尺寸决定，不能因圆角导致文字挤压。

### 4.3 字体与图标

- 字体继续使用系统字体栈，数字使用 tabular nums，保证倒计时、正确率、题量对齐。
- 功能图标统一走 `BaseIcon` 或可控矢量图标体系；后续如引入 lucide 类图标，必须统一封装后使用。
- 插画不能承担功能识别。用户识别“错题、复习、导入、题库、知识图谱”必须靠图标、标题和位置，而不是靠一张图猜。

## 五、动效准则

动效目标是让学习流程更顺，不是增加等待。

- 高频交互：`120ms-220ms`，只做按压、选中、切换、轻微位移。
- 页面切换和主面板展开：`220ms-360ms`，使用 transform / opacity / clip 类动画。
- 里程碑反馈：`360ms-700ms`，只在完成训练、连续学习达成、掌握度升级时出现。
- 禁止连续背景动画常驻运行。知识图谱可轻微呼吸，但必须能降级为静态。
- 用户必须能跳过或快速继续，不能让动画阻塞下一题、下一步或返回。

移动端构建时要预留低性能模式：关闭复杂 blur、降低阴影层数、停用大面积粒子或持续动画。

## 六、组件方向

### 6.1 App Shell

移动端壳不是普通 tab 页堆叠，而是“学习操作台”：

- 顶部：品牌、当前备考路径、同步/清洗状态，弱化传统导航栏。
- 中部：当前最该做的一件事，优先继续刷题、今日复习、资料导入结果。
- 底部：悬浮导航和主行动按钮，确保单手可达。
- 全局：底部安全区、刘海屏、安卓返回键、弱网和离线状态必须作为壳能力处理。

### 6.2 核心组件

| 组件 | 用途 | 设计约束 |
|------|------|----------|
| Command Bar | 首页/刷题页的主行动区 | 一个主按钮，最多两个次按钮，图标必须矢量化 |
| Segmented Control | 科目、题型、模式切换 | 不使用下拉作为高频切换，选中态要有明确滑块 |
| Training Panel | 答题、复盘、限时训练 | 题干阅读区必须稳定，不随反馈内容跳动 |
| Evidence Badge | 答案证据、题库清洗状态 | 明确区分 `matched`、`candidate`、`missing`，不伪装质量 |
| Mastery Surface | 知识点掌握与薄弱链路 | 可视化优先展示趋势和风险，不堆节点数量 |
| Import Timeline | 资料上传、解析、清洗、发布 | 让用户知道卡在哪一步，而不是只显示 loading |
| Result Sheet | 完成训练后的反馈 | 一屏内给出正确率、速度、薄弱点、下一步；避免多层弹窗 |

## 七、模块解耦策略

移动端改造顺序必须先打磨“积木”，再搭视觉壳，最后组装。

### 7.1 当前事实

`src/pages.json` 当前公开路由只有小程序提审所需的精简结构：首页、刷题、我的、登录/引导、题库、答题、错题、隐私协议。`src/pages/` 和 `docs/03-MODULE-INDEX.md` 中仍保留大量历史模块，例如资料导入、学习计划、知识图谱、AI 课堂、工具页、学校页、收藏页、学习详情页。这些模块不能直接全量塞回移动端，必须逐个审计。

### 7.2 模块边界

| 模块 | 移动端定位 | 解耦要求 |
|------|------------|----------|
| 资料导入/解析 | 高意图入口，保留 | 页面只负责任务发起和进度展示；解析、清洗、题库发布进入统一 service/store |
| 小程序轻入口 | 快速体验和引流 | 与移动端共用题库索引、训练记录、清洗状态，不复制业务判断 |
| 题库导航 | 主学习入口 | 科目、轨道、年份、训练模式独立成查询模型 |
| 答题引擎 | 核心训练能力 | 从 `do-quiz.vue` 拆出题目状态、计时、提交、反馈、结果、AI 解析 |
| FSRS 复习 | 长期留存能力 | 调度服务独立于页面，页面只消费今日队列和复习结果 |
| 错题本 | 学习资产 | 错题采集、聚类、复练、报告拆开，避免页面内完成全逻辑 |
| 知识图谱 | 护城河展示 | 数据模型、布局计算、渲染层分离，低性能设备可降级 |
| 学习计划 | 次级规划能力 | 与刷题/复习共享任务模型，不另建一套进度系统 |
| 个人中心/设置 | 账户与权益 | 不承载核心学习入口，避免“我的”变成功能杂物间 |

### 7.3 重复上传解析路径

移动端原有“上传资料解析”路径保留为正式入口，因为它对应高意图用户和完整资料处理链路。微信小程序端也保留轻入口，但只作为轻量触达和状态查看。两个入口背后统一到同一个能力：

```
用户入口（App 上传 / 小程序轻入口 / 管理后台导入）
  -> Resource Intake Contract
  -> Cleaning Queue
  -> Question Bank Release Gate
  -> Practice Index
  -> Quiz / Review / Mistake / Knowledge Graph
```

页面层不得直接判断 PDF 清洗质量、答案证据是否可发布、题库是否晋级。这些判断必须由清洗报告、发布门禁和共享 service 输出。

## 八、美术资源策略

当前阶段不生成图片资源，只预留资产位和提示词规范。

### 8.1 什么时候用图片生成

优先用代码、CSS、矢量图标和组件实现。只有以下场景允许使用 `gpt-image-2/2K` 生成：

- 品牌首屏或启动页需要高质感真实化背景。
- 新手引导需要表达“资料导入 -> 清洗成题 -> 点亮知识图谱”的高完成度场景。
- 空状态、分享卡片、里程碑卡片需要比纯组件更强的传播感。
- 复杂材质、光影、实物隐喻无法用代码稳定实现。

### 8.2 提示词要求

提示词必须具体、真实、商业化，避免“AI futuristic”“cyber glow”“magic orb”等空泛词。每条提示词至少包含：

- 使用场景：启动页、引导页、分享卡、空状态、背景纹理。
- 构图：主体位置、留白区域、是否需要放文字。
- 材质：玻璃、磨砂、纸张、金属、柔光、真实桌面等。
- 品牌色：深绿、Wise 绿、雾白、少量琥珀或蓝青。
- 禁止项：无 emoji、无卡通 mascot、无考试机构、无老师头像、无夸张 AI 光球。
- 输出要求：2K 原图，后续导出 `@2x/@3x`，压缩后再入库。

不得把图片 API Key、请求地址、授权文件或生成服务配置写入仓库、文档、提交信息或运行报告。

### 8.3 资产占位

后续 UI 方案中如果需要图片，先用明确占位命名：

- `mobile-hero-study-desk`
- `mobile-onboarding-import`
- `mobile-onboarding-cleaning`
- `mobile-onboarding-knowledge-graph`
- `mobile-empty-question-bank`
- `mobile-share-training-result`

每个占位必须写清尺寸、透明背景需求、压缩预算和替代纯代码方案。

## 九、移动端页面方向

这些是方向，不是当前实现任务。

| 页面 | 首屏任务 | 视觉基调 |
|------|----------|----------|
| 首页 | 告诉用户今天该做什么，并一键继续 | 深绿工作台 + 玻璃导航 + 量化学习资产 |
| 刷题 | 选择训练模式、题库轨道、继续上次训练 | 高效训练控制台，密度高但层级清楚 |
| 资料导入 | 上传、解析、清洗进度、发布状态 | 可信流程面板，像金融 App 的交易进度 |
| 答题 | 题干、选项、计时、反馈、证据 | 沉浸训练舱，阅读优先，反馈短促 |
| 错题/复习 | 今日复习队列、薄弱点、复练结果 | 学习资产仪表盘，不做惩罚感 |
| 知识图谱 | 看见强弱节点和下一步 | 可降级的 2D 网络/矩阵，不先上重 3D |
| 我的 | 账户、权益、同步、设置 | 克制，不成为功能堆场 |

## 十、实施顺序

1. **移动端路由与模块盘点**：以 `src/pages.json` 为准，列出已暴露、隐藏、历史遗留和应删除模块。
2. **功能积木解耦**：按资料导入、题库、答题、复习、错题、知识图谱、计划、账户拆出契约和状态边界。
3. **单模块全链路审计**：每个模块过一遍数据来源、错误态、空态、弱网、离线、权限、埋点、测试。
4. **移动端壳设计**：先做 App Shell、导航、全局状态、主题和动效 tokens。
5. **组装核心链路**：先组“导入/题库 -> 刷题 -> 反馈 -> 错题/复习 -> 知识图谱”，再补计划和增长功能。
6. **真机验收**：iOS、Android、H5 移动端分别验收首屏、答题、导入、离线、返回键、低性能模式。

## 十一、验收口径

设计阶段通过条件：

- 文档规则被确认，没有继续争论“幼稚游戏化”和“成熟商业感”的方向。
- 每个页面都有明确首屏任务，不存在只展示品牌口号的首页。
- 每个视觉资产都有纯代码替代方案或生成理由。
- emoji、AI 光球、儿童 mascot、卡片套卡片被明确禁止。

实现阶段通过条件：

- 移动端构建：`npm run build:app` 通过。
- H5 移动预览：关键页面在 375x812、390x844、360x800、430x932 视口无文字溢出和元素重叠。
- 主链路真机：登录/引导、导入状态、题库进入、答题、错题、FSRS 复习、知识图谱降级均可跑通。
- 性能：首屏无长时间白屏；高频交互不依赖大面积 blur 或持续动画。
- 资产：生成图不含密钥、平台水印、品牌侵权元素、老师/机构信息；入库前完成压缩和尺寸审计。
