# 微信小程序 UI 重设计规格书

> 状态：进行中
> 优先级：最高
> 更新日期：2026-04-28
> 目标：以 Wise 绿色金融产品质感为参考，重构小程序端为成熟、沉浸、轻量的备考刷题体验

## 一、重构结论

当前小程序已有 3 个主 Tab：`首页`、`刷题`、`我的`，并已通过 `pages.json` 启用 `custom tabBar`，实际底部导航由 `src/components/layout/custom-tabbar/custom-tabbar.vue` 渲染。这符合本轮“移除微信原生导航栏、使用自定义悬浮导航”的技术基础。

旧版设计规格强调原生 TabBar、emoji 图标和无图片依赖，已经不符合本轮方向。本轮重构改为：

- 彻底移除猫头鹰、3D 卡通、低幼化游戏素材。
- 保留学习产品的轻量感，但视觉表达转向成熟、金融级、清爽向上的绿色系统。
- 页面采用现代沉浸式布局：白/绿背景、不规则大玻璃卡片、柔和光影和低噪声信息密度。
- Tab 切换先行，完成后暂停，让开发者工具中实机验收再继续页面级重构。
- PNG 资源先输出完整物料清单和提示词，由在线工具统一生成后替换。

## 二、视觉方向

### 2.1 参考产品

| 参考 | 可借鉴点 | 不照搬点 |
|------|----------|----------|
| Wise | 高明度绿色、清晰金融信息层级、低噪声留白 | 不做金融交易界面，不复制品牌图形 |
| Apple iOS | 磨砂玻璃、悬浮层、弹性按压反馈、安全区域处理 | 不堆叠过多透明层，避免低端机性能问题 |
| Duolingo 训练反馈 | 快速正反馈、节奏感、完成感 | 不使用低幼卡通形象和夸张儿童化颜色 |

设计基调命名为：**清醒生长感**。

三条具体原则：

- **成熟**：不出现猫头鹰、卡通吉祥物、emoji、幼儿化奖章。
- **轻量**：页面第一眼不压迫，信息分层靠尺寸、透明度、阴影、空间完成。
- **上进**：绿色用于进度、正确、增长、行动，不做荧光感和扎眼饱和。

### 2.2 Wise 绿基准

主色对标 Wise 绿，而不是 ZA Bank 绿。建议基准值：

| Token | 值 | 用途 |
|-------|----|------|
| `--brand-green` | `#9FE870` | 主品牌绿、选中态、关键进度 |
| `--brand-green-strong` | `#58CC02` | 需要更强行动感的按钮或高亮 |
| `--brand-green-deep` | `#163300` | 深绿文字、Logo 深色笔画 |
| `--brand-green-soft` | `#ECFBE3` | 玻璃卡片内浅绿底 |
| `--page-mint` | `#F3FAED` | 页面浅绿背景 |
| `--page-white` | `#FFFFFF` | 主要内容面 |
| `--ink` | `#142117` | 主文字 |
| `--ink-soft` | `#5D6B61` | 次文字 |
| `--line-soft` | `rgba(22, 51, 0, 0.08)` | 玻璃边界和分割线 |

颜色使用比例：

- 60% 白色/浅绿背景。
- 25% 玻璃卡片和浅绿色面。
- 10% 深绿文字和操作元素。
- 5% 辅助色，用于风险、倒计时、错误和高压状态。

## 三、Logo 方向

Logo 必须简洁大气，避免“考试机构”和“儿童学习软件”气质。建议做 **书本 + 上升路径 + 东方木气** 的抽象组合。

### 3.1 图形结构

- 主体：一本打开的书，抽象为两个不对称叶片。
- 上升：中间负形形成向上的阶梯、箭头或折线。
- 五行方位：绿色属木，对应东方和生发。Logo 可以让右上方向略有延展，暗合“东方生发、向上进阶”。
- 避免：猫头鹰、博士帽、毛笔、卷轴、状元、锦鲤、龙凤、佛道符号等显性玄学元素。

### 3.2 Logo 提示词

中文提示词：

> 极简现代 App Logo，绿色为主色，抽象打开的书本与向上进步路径融合，负形形成向上阶梯，几何构成，金融科技品牌质感，成熟、干净、大气，暗含东方木气和生发方向，白色背景，扁平矢量风格，适合作为微信小程序图标，无文字，无卡通，无猫头鹰，无博士帽。

英文提示词：

> Minimal modern app logo, green primary color, abstract open book combined with an upward progress path, negative space forming rising steps, geometric fintech brand quality, mature, clean, premium, subtle east wood element symbolism, white background, flat vector style, suitable for WeChat mini program icon, no text, no cartoon mascot, no owl, no graduation cap.

## 四、页面级布局规范

### 4.1 页面壳

- 背景使用浅绿到白的低对比渐变，不能使用蓝紫渐变、暗黑赛博、纯灰工具风。
- 页面顶部保留自定义导航栏，但视觉上要轻：透明、无硬边框、标题不抢内容。
- 页面底部为 Apple 拟物态玻璃悬浮 TabBar，安全区域必须适配 iPhone 刘海屏和安卓全面屏。

### 4.2 玻璃卡片

页面摒弃传统考试工具的直线列表布局，改为不规则大卡片组合：

- 首页：一张主进度大卡 + 两张异形统计卡 + 一张最近学习半宽卡。
- 刷题：题库导航卡、模式入口卡、倒计时/速度训练卡、资源状态卡分层排列。
- 我的：个人身份卡、学习资产卡、设置入口卡、同步状态卡。

卡片规则：

- 大小不一，但纵向节奏清晰。
- 每屏最多 3 个视觉重点。
- 不使用 emoji、廉价小图标和大段提示文案。
- 卡片圆角可在 24rpx 到 44rpx 间变化，但同一模块内保持一致。
- 玻璃效果只用于悬浮层和一级卡片，不在卡片里继续套卡片。

### 4.3 字体与文字

小程序端使用系统中文字体栈：

```scss
font-family: -apple-system, BlinkMacSystemFont, 'PingFang SC', 'Helvetica Neue', sans-serif;
```

文字规则：

- 标题短而明确，不写“智能助力学习成长”这类空泛文案。
- 错误和空状态不写大段说明，优先给一个可行动按钮。
- 数字使用 `font-variant-numeric: tabular-nums`，用于倒计时、正确率、刷题速度、积分。

## 五、底部导航栏规格

本项是第一阶段实现目标。

### 5.1 功能范围

- 继续使用 `src/components/layout/custom-tabbar/custom-tabbar.vue`。
- 不恢复微信原生可见 TabBar。
- 保持 3 个 Tab：`首页`、`刷题`、`我的`。
- 支持点击切换。
- 支持横向滑动切换：在 TabBar 上左右拖动，松手后跳到相邻 Tab。
- 切换过程有 Q 弹感、轻微放大和胶囊滑块位移。
- 保留轻振动反馈，失败时静默降级，不阻塞导航。

### 5.2 视觉结构

```
┌─────────────────────────┐
│                         │
│       页面内容           │
│                         │
│    ╭────────────────╮    │
│    │ 首页  刷题  我的 │    │
│    ╰────────────────╯    │
└─────────────────────────┘
```

结构说明：

- 外层：透明定位容器，不挡页面点击。
- 内层：悬浮玻璃胶囊，宽度约 `80vw`，最大不超过 `600rpx`。
- 背后：半透明白绿玻璃、柔和阴影、顶部高光。
- 内部：一个可移动的绿色玻璃滑块作为选中态，Tab 文本和图标位于其上。

### 5.3 交互细节

| 行为 | 反馈 |
|------|------|
| 点击未选中 Tab | 滑块横向移动，目标 Tab 图标放大，轻振动 |
| 点击当前 Tab | 不跳转，可做轻微按压反馈 |
| 左右拖动超过阈值 | 切换到相邻 Tab |
| 拖动未超过阈值 | 回弹到当前 Tab |
| 切换失败 | 尝试 `reLaunch`，仍失败再走安全导航 |

动效约束：

- 只动画 `transform` 和 `opacity`。
- 禁止 `transition: all`。
- 弹性曲线使用 `cubic-bezier(0.34, 1.56, 0.64, 1)`。
- 过渡时长控制在 220ms 到 360ms。

## 七、刷题与资源系统设计方向

本节用于后续阶段，不在第一阶段一次性实现。

### 7.1 资源同步判断

现有文档 `docs/15-BAIDU-API-VALIDATION.md` 已确认：百度网盘开放 API 更适合作为管理员离线存储后端，而不是用户端 CDN。资源群文件能否被 API 直接调用仍需单独验证；在没有官方可用群组 API 前，不应把“自动读取群组”写成确定能力。

建议路线：

1. 管理员层：使用百度网盘保存原始 PDF。
2. 同步层：本地脚本或桌面一键同步工具定期对比文件名、大小、修改时间和哈希。
3. 清洗层：将 PDF 转换为结构化题目、答案、解析、知识点编号。
4. 分发层：小程序只读取 Laf 数据库或内置轻量 JSON，不直接碰原始网盘文件。

可调研方案：

- Chrome 插件：适合半自动转存资源群文件，但依赖网页登录状态，稳定性和合规性风险较高。
- Mac 菜单栏/桌面一键同步 App：适合管理员自用，可调用本地脚本、OAuth Token 和清洗管线。
- 定时脚本：适合每日凌晨处理，但对验证码、网页登录态和网盘策略变化更敏感。

### 7.2 法务与内容清洗红线

- 小程序前端、题库分类、题目展示中不能出现老师、机构、资源群、广告来源等字眼。
- 分类只能保留：年份、考试类型、学科、题型、知识点、难度、真题/模拟/练习类型。
- 原始 PDF 只作为用户/管理员自有资料的加工输入，不在产品中展示机构归属。
- 题目解析必须可追溯到原始页码和题号，避免 AI 编造。

### 7.3 OCR 与 PDF 解析

优先顺序：

1. PDF 原生文本层提取。
2. macOS Vision / Apple OCR 类本地识别方案，用于扫描版 PDF。
3. 仅在本地 OCR 不可用或质量不达标时，才考虑收费模型。

题目结构必须包含：

- 原始文件 ID。
- 页码。
- 原题号。
- 题干。
- 选项。
- 正确答案。
- 解析。
- 知识点编号。
- 学科与章节。
- 置信度。
- 人工复核状态。

### 7.4 刷题游戏化

刷题不应只是无限列表。后续设计为“短局制闯关”：

- 每局 5 到 12 题。
- 每题有选择时限。
- 总时长和单题反应时共同影响得分。
- 越快且正确，奖励越高。
- 错题进入 FSRS 复习队列。
- 可加入 ELO 或能力分，但只用于匹配难度和展示进阶，不制造焦虑排行榜。

关键反馈：

- 正确：轻振动 + 绿色扩散 + 分数上浮。
- 错误：短促反馈 + 正确答案显露 + 不打断节奏。
- 连击：抽象能量环，不用火焰和金币。
- 升级：向上阶梯光效，不用奖杯和皇冠。

## 九、验收标准

第一阶段验收：

- 微信开发者工具中不出现原生可见 TabBar。
- 自定义 TabBar 悬浮在底部，不遮挡页面主操作。
- 点击三个 Tab 可切换。
- 在 TabBar 上左右滑动可切换相邻 Tab。
- 选中滑块有可见横向移动和回弹效果。
- 未出现 emoji 图标。
- 控制台无新增运行时错误。
- `npm run build:mp-weixin` 可通过。

整体重构验收：

- 所有 `.png` 完成替换。
- 页面首屏成熟、清爽，无猫头鹰、卡通人物、火焰金币奖杯等旧语义。

- 题库分类不出现老师和机构相关字眼。
- 刷题流程有时间压力、即时反馈、复习调度和阶段完成感。
